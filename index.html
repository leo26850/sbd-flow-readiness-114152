Why fixes that were already made didn't take. When a message is added to a flow, Klaviyo clones the template and the flow keeps its own private copy. Editing the original afterwards changes nothing the flow sends. Earlier fix passes edited the originals — those are now clean, all 25 of them — but the flow copies, which are the ones that actually go out, still carry the old broken content. That single mechanic explains every defect in this report.

SBD - Review Request - Service Recovery WcZM6r fix first

Highest priority, and the only item here with legal exposure. The recovery text message carries no “Reply STOP” opt-out line — every other SBD text does. Klaviyo treats this message as marketing, so the line is required, and it sends to people who have just complained.

Separately, three variables in both the email and the text render as nothing, so customers currently read “this is  from Smith Bros” and “Is  still the best way to reach you ?”. The fix is to pull the contact the customer actually typed into the feedback form, fall back to their email, and name a real sender.

Trigger is live and working — three feedback-form submissions, most recent 27 July 21:47.

SBD - Email-to-SMS Insider Push TTnQDk fix first

Section 4 · How the fixes get made

Fix route, and why it's hands-on

A constraint set for this work: no flow may be renamed and no flow may change identity. That rules out the fastest route and settles how the work gets done.

  • Rebuilding the flows is off the table. The quick fix would have been to rebuild each flow so Klaviyo re-copies clean content. But rebuilding always mints a new flow identity, which breaks the constraint — and it would break every saved report and link that points at these flows.
  • Klaviyo's interface can do all of it, in place. Message copy, text bodies, exit rules and the one-day delay can all be edited directly on the existing flows. Names and identities are untouched. This is the route we'll take.
  • The trade-off is that it's manual — 12 messages across 6 flows, plus exit rules and one delay. Klaviyo's API offers no way to write flow message content, so none of this can be scripted.
  • Checking the work is automated, and that matters. A previous pass reported 15 templates as fixed while silently writing to none of them. A verification script now re-reads the live account and asserts every count in this report, so “fixed” means proven, not assumed.

Section 6 · For the record

Caveats and notes

  • One claim we could not verify. An earlier audit found that six of the nine flows have no exit rule at all. Klaviyo's API does not expose flow-level rules, so we could not independently confirm it — it's reported here as inherited, not verified. Each rule will be confirmed visually in the interface as it's added.
  • Vehicle details only work in some flows. The vehicle is attached to the completed-service event, not stored on the customer record — of 600 profiles sampled, none carried it. So “your 2019 Tahoe” is only possible in the four event-triggered flows. The other five must keep generic wording; anything else would render blank.
  • Last week's Flash campaign names don't match their send dates. Four campaigns labelled “Tue Jul 28” and “Wed Jul 29” all actually sent on Monday 27 July at 18:30 UTC. The names are being left as they are, deliberately — this footnote is the record, so reporting isn't read wrong later. The A/B comparison itself is still valid: both arms were treated identically.
  • The same send also skipped the channel stagger. Text and email went out in the same minute rather than text Tuesday, email Wednesday, so anyone on both lists got both at once.
