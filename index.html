What had gone wrong, and why earlier fixes hadn't taken. When a message is added to a flow, Klaviyo clones the template and the flow keeps its own private copy. Editing the original afterwards changes nothing the flow sends. Earlier fix passes edited the originals, so those read as clean — while the flow's copies, the ones that actually go out, still carried a dead “Book” button, blank variables and the old brand name. That single mechanic explains every defect found. All 12 have now been corrected on the flow copies themselves.

Section 5 · How it was done

Fixed in place, nothing rebuilt

A constraint was set for this work: no flow may be renamed and no flow may change identity. That ruled out the obvious route and turned out to lead somewhere better.

  • Rebuilding was off the table. The original plan was to rebuild each flow so Klaviyo re-copies clean content. But rebuilding always mints a new flow identity, which would break every saved report and link pointing at these flows.
  • It turned out the flows could be edited directly instead. A newer version of Klaviyo's interface allows the message content of an existing flow to be updated in place. So the fixes were applied to the live flows themselves — names, identities and draft status all untouched, and confirmed afterwards: all nine names byte-identical, all nine IDs unchanged, all nine still draft.
  • Everything was backed up first, and every single write was proven by reading the message back rather than trusting that the change had gone through.
  • Nothing was activated. No message has been sent, and no flow was taken out of draft.

Section 7 · For the record

Caveats and notes

  • One claim we could not verify. An earlier audit found that six of the nine flows have no exit rule at all. Klaviyo's interface does not expose those rules to us programmatically, so we could not independently confirm it — it's reported here as inherited, not verified. Each rule will be confirmed visually as it's added.
  • Vehicle details only work in some flows. The vehicle is attached to the completed-service record, not stored on the customer — of 600 customers sampled, none carried it. So a specific vehicle can only appear in the four flows triggered by a service; the other five keep generic wording, because anything else would render blank. The fixes respect that split.
  • Last week's Flash campaign names don't match their send dates. Four campaigns labelled “Tue Jul 28” and “Wed Jul 29” all actually sent on Monday 27 July at 18:30 UTC. The names are being left as they are, deliberately — this footnote is the record, so reporting isn't read wrong later. The A/B comparison itself is still valid: both arms were treated identically.
  • The same send also skipped the channel stagger. Text and email went out in the same minute rather than text Tuesday, email Wednesday, so anyone on both lists got both at once.
